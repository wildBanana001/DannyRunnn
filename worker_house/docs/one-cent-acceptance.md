# 正式售卖前的一分钱验收

负责人已确认：先按 ¥0.01 单价做完整测试，稳定后再确认正式价格。本文件是执行/记录清单，未勾选项不代表已验证。

## 验收前置条件

- [ ] 记录目标云环境、BFF 版本、体验版小程序版本、测试负责人和窗口。
- [ ] BFF CI 中真实 MySQL 集成测试、小程序生产包扫描均通过。
- [ ] 备份真实活动/商品目录；确认 MySQL 首次种子不会覆盖运营数据。
- [ ] 暂停新单，排空在途创建请求，处理/核对已有待支付单后再调价。保留回调和历史查单。
- [ ] 通过受控工具预览目标 ID 与原单价，再应用一分钱价格并保存快照；读取接口核对生效。修改仓库种子不能替代这一步。
- [ ] 明确测试用户和有白名单权限的核销管理员；无关用户不得参与这一分钱窗口。体验版并不自动隔离生产 BFF：若使用生产服务且正式版也能开单，要先安排受控窗口或独立验收环境，不能假设只有测试者能看到低价。
- [ ] 指定一个可报名的测试活动及档期。仓库种子活动均已结束；不要擅自重新开放历史活动，也不要把它们无法报名误判为支付故障。
- [ ] 确认下单数量及运费；¥0.01 是单价，多件或有运费时总额并非一分钱。测试期间不自动改变运费、库存、限购、履约方式或上架状态。

调价后可在 BFF 目录使用 `BFF_BASE_URL=https://已确认的服务域名 npm run check:release -- --expect-shop=closed --expect-test-prices`，检查公开目录响应是否都为 ¥0.01。测试窗口批准开单后将 `closed` 改为 `open`。活动分页及无交易检查的边界仍以发布清单为准，不能用这条命令代替真实支付验收。

## 受控调价与撤销

工具为 `worker_house_bff/scripts/test-prices.mjs`，在已安装 BFF 依赖的开发/运维目录运行，不依赖生产镜像内包含这个脚本。通过已批准的数据库私网或安全连接执行；连接信息使用本地受控环境中的 `MYSQL_URL`，或 `MYSQL_ADDRESS`、`MYSQL_USERNAME`、`MYSQL_PASSWORD`、`MYSQL_DATABASE`，没有默认库。不要把密码写入命令、聊天或 Git。

必须指定 `--catalog=activities|products` 与 1–100 个准确 ID，不接受全库或通配符。下例 ID 与路径只是格式示例，执行前必须替换成已核对的目标和仓库外的备份路径：

```bash
# 默认仅预览：只读事务，不调价、不建表、不种数据、不写快照。
node scripts/test-prices.mjs --catalog=products --ids=product-id-1,product-id-2

# 审核预览、停新单并排空在途请求后才应用。
node scripts/test-prices.mjs --catalog=products --ids=product-id-1,product-id-2 --apply --confirm-sales-paused --snapshot=/absolute/secure-backups/products-one-cent.json

# 撤销也先预览，目标和快照必须完全匹配。
node scripts/test-prices.mjs --catalog=products --ids=product-id-1,product-id-2 --restore=/absolute/secure-backups/products-one-cent.json
node scripts/test-prices.mjs --catalog=products --ids=product-id-1,product-id-2 --restore=/absolute/secure-backups/products-one-cent.json --apply --confirm-sales-paused
```

活动使用 `--catalog=activities`，保存独立快照。工具只改单价 `price` 和必要版本字段，保留 `originalPrice`、运费、库存、限购、上下架、活动档期和所有历史订单。目录必须已经初始化；未完成种子状态检查时拒绝操作。

同一次命令的所有 ID 在一个事务内完成；商品与活动两次命令不是一个跨目录事务，任何一步失败都保持停新单并核对结果，不能直接开卖。已经是 ¥0.01 的目标显示 no-op；全部无需变更时不创建快照。

有变更时，工具先以独占方式创建权限 `0600` 的原价快照，再写数据库；已有文件不覆盖。快照不含凭证、连接地址、订单或用户资料。恢复校验目标库指纹、全部 ID、本轮测试价和版本，发现后续运营改动时拒绝覆盖。

快照写成功不等于数据库提交成功。如果提交过程中断线，不要直接换个文件重跑，应核对当前价格/版本后决定恢复或继续。价格恢复不会关闭旧待支付单，也不会撤销用户已经拿到的微信支付参数；测试收尾必须处理在途交易。
